# CallManager (WebRTC-звонки)

`CallManager` управляет жизненным циклом звонка и потоками поверх SIP/WebRTC.

## Назначение

- Запуск и завершение исходящих/входящих звонков.
- Управление MCU-сессией и receive-only сессией зрителя.
- Оркестрация состояния звонка через `CallStateMachine`.
- Использование `CallSessionState` (инжектируется из `SipConnector`) для role-orchestration.

## Ключевые возможности

- Управление WebRTC-соединением и медиа-потоками.
- Обработка переходов роли участника и переключение активного stream manager.
- Отложенный запуск `RecvSession` при гонке API-событий и выдачи JWT.
- Поддержка presentation-call через заголовок `x-vinteo-presentation-call: yes`.
- Проверка сигнализации перед re-INVITE/UPDATE клиента: `MCUSession` вызывает `waitForSignaling`, который `SipConnector` передаёт из `AutoConnectorManager`. Без подтверждения re-INVITE не отправляется, а `renegotiate()`/`restartIce()` возвращают `false`; досылается только re-INVITE `replaceMediaStream()` — сразу по успешному ping, без повторной проверки, если другой re-INVITE не ждёт проверки и досылка уже не идёт; пометка снимается, только когда `renegotiate()` вернул `true`; re-INVITE от сервера проверка не затрагивает. Подробнее — в [рецепте автопереподключения](../../../recipes/auto-reconnection.md#проверка-сигнализации-перед-re-invite).
- Отключение прежнего подключения участника перед исходящим звонком через [StaleParticipantManager](../StaleParticipantManager/index.md); адрес сервера — из `getSipServerUrl` в tools (`TCallManagerTools`).

## Основные методы

| Метод                              | Назначение                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `startCall()`                      | Запуск исходящего звонка (с передачей `extraHeaders` в state-machine контекст): после `start-call` отключает прежнее подключение участника, затем отправляет `INVITE` через UA, взятый уже после отключения, поэтому фаза `call:connecting` может быть длиннее. Ошибка отключения — `failed` с `originator: 'local'` и `cause: 'Internal Error'`, `INVITE` не уходит. Вытесняет идущий запуск без события. |
| `answerToIncomingCall()`           | Ответ на входящий звонок; во время отключения прежнего подключения тихо отменяет запуск исходящего: без `failed`, машина звонка сбрасывается напрямую, `startCall` отклоняется ошибкой отмены, `INVITE` не уходит. `SipConnector.answerToIncomingCall` перед ответом разоружает автоперезвон.                                                                                                              |
| `endCall()`                        | Завершение текущего звонка; во время отключения прежнего подключения отменяет запуск: `failed` с `originator: 'local'` и `cause: 'Canceled'`, `INVITE` не уходит.                                                                                                                                                                                                                                          |
| `cancelStartCall()`                | Тихая отмена запуска во время отключения прежнего подключения: без `failed`, машина звонка сбрасывается в `call:idle`, `startCall` отклоняется ошибкой отмены, `INVITE` не уходит. После ушедшего `INVITE` ничего не делает. Вызывают `CallReconnectRuntime.cancelAll()` при идущей попытке перезвона и `SipConnector.disconnect()` без connect + call session.                                            |
| `replaceMediaStream()`             | Замена локального медиа-потока в активной сессии.                                                                                                                                                                                                                                                                                                                                                          |
| `restartIce()`                     | Перезапуск ICE-процедуры соединения (`false`, если re-INVITE не отправлен).                                                                                                                                                                                                                                                                                                                                |
| `subscribeToApiEvents(apiManager)` | Подписка на API-события state-machine и `CallSessionState`.                                                                                                                                                                                                                                                                                                                                                |

## Внутренние компоненты

| Компонент                 | Роль                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------- |
| `MCUSession`              | Основная SIP/RTC-сессия участника конференции; единая точка отправки re-INVITE клиента. |
| `RecvSession`             | Receive-only сессия для spectator-режима.                                               |
| `DeferredCommandRunner`   | Отложенный запуск `RecvSession` до достижения состояния `IN_ROOM`.                      |
| `RemoteStreamsManager`    | Управление удалёнными потоками (`main` и `recv`).                                       |
| `CallStateMachine`        | Валидация переходов и нормализация контекста звонка.                                    |
| `CallSessionState`        | Внешний read-model: роль, `license`, производные role-флаги.                            |
| `StaleParticipantManager` | Отключение прежнего подключения участника внутри `startCall`.                           |
