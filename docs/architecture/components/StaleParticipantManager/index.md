# StaleParticipantManager (Отключение прежнего подключения участника)

**Назначение**: перед исходящим звонком отключает «устаревшего участника» — прежнее подключение участника, которое сервер может держать после звонка, завершённого не сервером: обрыв сети, остановка клиента, локальный отбой без ответа сервера на `BYE`.

## Ключевые возможности

- Запоминает подключение при входе в комнату: токен комнаты из `CallStateMachine.onInRoomCredentialsChange` и адрес сервера из `getSipServerUrl` в tools `CallManager`.
- Помечает подключение устаревшим при любом завершении звонка не сервером: `end-call` (локальный отбой), `ended`/`failed` с `originator` `local` или `system` — в том числе остановка клиента при офлайне или смене сети и сетевые причины JsSIP. Завершение сервером (`originator: 'remote'`) подключение забывает.
- После `end-call` следит за ответом сервера на `BYE` этого отбоя (UA из `getUa` в tools `CallManager`): любой финальный ответ значит, что сервер подключение снял, — устаревший участник забывается, а идущее ожидание подтверждения завершается успехом без новых запросов. Без ответа (обрыв транспорта, таймаут транзакции) или без UA подключение остаётся устаревшим.
- Помнит устаревшего участника 60 с с момента завершения звонка; срок проверяется перед звонком. Позже запроса нет: сервер сам убирает такого участника примерно за 15 с.
- Работает внутри `CallManager.startCall` — перед каждым исходящим звонком и каждой попыткой перезвона `CallReconnectManager`: после события `start-call`, до создания SIP-сессии. Повторяет запрос раз в 1 с, пока сервер не подтвердит отключение ответом `401`, но не дольше 20 с. После любого исхода, кроме отмены, устаревший участник забывается.
- Отключает устаревшего участника, только если текущий адрес сервера совпадает с его сервером; устаревшего участника другого сервера забывает без запроса. Без конфигурации соединения запроса нет, и устаревший участник сохраняется до следующего звонка.
- Отменяется вместе с запуском звонка по сигналу `CallManager` — см. [отмену запуска](#отмена-запуска).
- Создаётся и хранится в приватном поле `CallManager`, из пакета не экспортируется; поля у `SipConnector` нет.

## Зачем нужен

Наблюдения на тестовом сервере:

- пока устаревший участник не отключён, сервер отвечает на новый `INVITE` `200 OK`, затем шлёт `CANCEL` и не пускает участника в комнату: звонок висит в `connecting` и примерно через 27 с завершается с `local` `Internal Error`;
- сам сервер убирает устаревшего участника примерно через 15 с (`BYE` с `DTLS-FAILED`);
- после ответа `204` прежнее подключение фактически отключается примерно через 1,1 с;
- если участника на сервере нет, ответ — `401` «You are not participating».

Наблюдения на другом тестовом сервере: после первого запроса подтверждение `401` приходит через 1–4 с, а повторный запрос выполняет команду отключения, если первая потерялась.

## Публичный API

| Метод/поле                | Назначение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `disconnectStale(signal)` | Без устаревшего участника сразу завершается. Если с завершения звонка прошло больше 60 с, забывает его без запроса. Без конфигурации соединения завершается без запроса и сохраняет устаревшего участника. Если сервер устаревшего участника не совпадает с текущим адресом сервера, забывает его без запроса. Иначе отправляет запрос отключения и ждёт подтверждения: `401` — успех; `2xx` — пауза 1 с и повтор тем же токеном; без `401` за 20 с от первого запроса — успех без подтверждения, в том числе когда предел обрывает зависший запрос. Другой статус на любом запросе — `Error('Stale participant disconnect failed with status N')`, сетевая ошибка — отказ, который не является отменой. Отмена `signal` прерывает запрос и паузу: отключение отклоняется `signal.reason`, устаревший участник сохраняется для следующего звонка. После любого другого исхода устаревший участник забывается. |

## Жизненный цикл подключения

События звонка меняют только подключение текущего звонка; устаревшего участника заменяет лишь вход в комнату.

| Событие                                     | Подключение текущего звонка      | Устаревший участник                      |
| ------------------------------------------- | -------------------------------- | ---------------------------------------- |
| Вход в комнату (новый токен)                | Заменяется новым подключением    | Заменяется                               |
| `end-call` (локальный отбой)                | Становится устаревшим участником | Не меняется                              |
| Ответ сервера на `BYE` этого отбоя          | —                                | Забывается, ожидание завершается успехом |
| `ended`/`failed` от `local` или `system`    | Становится устаревшим участником | Не меняется                              |
| `ended`/`failed` от `remote`                | Забывается                       | Не меняется                              |
| `disconnectStale()` позже 60 с после звонка | —                                | Забывается без запроса                   |
| `disconnectStale()` при другом сервере      | —                                | Забывается без запроса                   |
| `disconnectStale()` без конфигурации        | —                                | Не меняется, запроса нет                 |
| Завершение отключения, кроме отмены         | —                                | Забывается                               |
| Отмена `signal`                             | —                                | Не меняется                              |

Без адреса сервера при входе в комнату подключение не запоминается.

## Запрос

`POST https://<sipServerUrl без завершающего />/api/v2/participants/self/disconnect` с заголовком `Authorization: Bearer <токен комнаты>`, без тела, `credentials: 'same-origin'`. Адрес сервера `CallManager` получает из `tools.getSipServerUrl`: `SipConnector` передаёт `sipServerUrl` текущей конфигурации подключения. Сервер запоминается на момент входа в комнату; запрос уходит, только если он совпадает с текущим адресом (оба без завершающего `/`); без конфигурации соединения запроса нет, и устаревший участник сохраняется. Ответ `2xx` подтверждает только приём команды, поэтому после него запрос повторяется тем же токеном через паузу 1 с, пока сервер не ответит `401`. Общий предел — 20 с от первого запроса: после него отключение завершается без подтверждения, и звонок всё равно уходит. Отдельного таймаута у запроса нет: зависший запрос обрывает тот же предел. Запрос и пауза прерываются также отменой `signal`; `fetch` берётся глобальный в момент вызова. Интервал, предел и срок 60 с — внутренние константы без публичных опций.

## Встраивание

Порядок в `CallManager.startCall`:

1. Замещает незавершённый прежний запуск (см. [отмену запуска](#отмена-запуска)) и создаёт `AbortController` нового.
2. Эмитит `start-call` с `answer: false`: машина звонка переходит в `call:connecting`, приложение видит идущий исходящий звонок.
3. `disconnectStale(signal)`.
4. Проверяет, что запуск не прерван; прерванный запуск отклоняется ошибкой отмены без `INVITE`.
5. `MCUSession.startCall` → `INVITE`. UA для `INVITE` берётся после отключения: если клиент переподключился во время ожидания, звонок уходит через новый UA.

- На время отключения фаза подключения длиннее: обычно на 1–4 с, не больше чем на 20 с. Статусы звонка те же, что без отключения.
- Ошибка отключения: после отказа отключения `CallManager` эмитит `failed` с `originator: 'local'`, `cause: 'Internal Error'` и текстом ошибки в `message.body`; `startCall` отклоняется исходной ошибкой, `INVITE` не уходит. Приложение получает обычный отказ звонка: например, `SipConnectorFacade.callToServer` вызывает `onFailProgressCall`.
- Попытка перезвона — `getCallParameters` → `startCall`: ошибка отключения приходит отказом `startCall` и считается неуспешной попыткой по `canRetryOnError` и `maxAttempts`.
- `answerToIncomingCall` устаревшего участника не отключает.

## Отмена запуска

Пока `INVITE` не ушёл, запуском владеет `CallManager`: у каждого запуска свой `AbortController`, его сигнал получает `disconnectStale`. Проверка после шага действует и без устаревшего участника, и в такте между ответом `401` и продолжением запуска. Прервать запуск можно двумя способами:

- **Завершение** — `endCall()`, через него `SipConnector.hangUp()`, `SipConnector.disconnect()` и сессия connect + call. Громко: `end-call`, затем `failed` с `originator: 'local'`, `cause: 'Canceled'`, как у JsSIP при отмене исходящего звонка; машина звонка уходит в `call:idle`, а не остаётся в `call:disconnecting`.
- **Замещение** — новый `startCall()` или `answerToIncomingCall()`. Тихо, без `failed`, чтобы не сломать состояние нового звонка: ответ сбрасывает машину звонка напрямую и переводит её в `call:connecting` с контекстом ответа, новый звонок продолжает в `call:connecting`.

В обоих случаях запрос и пауза прерываются, `startCall` отклоняется ошибкой отмены, `INVITE` не уходит, устаревший участник сохраняется для следующего звонка. Приложение получает обычный отказ звонка, например `onFailProgressCall` в `SipConnectorFacade.callToServer`.

Перезвон начатый звонок не отменяет: `disarm`, `cancelCurrentAttempt` и повторный `arm` прекращают только планирование попыток, а отключение и `INVITE` уже начатой попытки продолжаются — так же, как раньше на фазе `INVITE`. Такой звонок завершают `hangUp()`/`disconnect()` или замещают новый звонок и ответ на входящий; `SipConnector.call()` и `SipConnector.answerToIncomingCall()` перед этим разоружают автоперезвон.

## Ограничения и риски

- Гонка после `204` закрыта ожиданием подтверждения `401`. Исключение — предел 20 с: если подтверждения нет, звонок уходит, и новый `INVITE` может застать устаревшего участника ещё на сервере.
- Без повтора после ошибки: если запрос цикла получил другой статус или сетевую ошибку, устаревший участник забывается, текущий звонок не уходит, а следующий идёт без запроса; прежнее подключение может оставаться на сервере до его собственного таймаута.
- Ожидание подтверждения задерживает звонок: обычно на 1–4 с, не больше чем на 20 с.
- Ошибка отключения во время попытки перезвона отклоняет попытку; следующую попытку или завершение решает `CallReconnectManager` через `canRetryOnError` и лимит попыток: см. [координацию с connect + call session](../../../recipes/call-auto-redial.md#координация-с-connect-call-session).
- Повторный звонок после обычного отбоя уходит без запроса: сервер ответил на `BYE`. Если звонок начат раньше ответа, ожидание длится до ответа на `BYE` (обычно доли секунды).
- Ответ на `BYE` JsSIP публично не сообщает: используются внутреннее событие UA `newTransaction` и состояние транзакции `BYE`. При обновлении `@krivega/jssip` это место надо проверить в первую очередь.
- Код ответа на `BYE` из состояния транзакции не виден: любой финальный ответ, в том числе `401`/`407`, `408` и `5xx`, считается снятием подключения. На тестовых серверах `BYE` получает `200 OK` без запроса авторизации; на запрос авторизации JsSIP повторяет `BYE` с учётными данными.
- Сервер не отвечает `401` на токен звонка с презентацией во втором потоке (screencast): если такой звонок оборвался без ответа на `BYE`, следующий звонок ждёт полный предел 20 с.
- Смена аккаунта на том же сервере в течение 60 с после звонка: перед первым звонком нового аккаунта уходит запрос с токеном прежнего, и его ошибка отклоняет этот звонок.
- Состояние хранится только в памяти экземпляра `CallManager`: после перезагрузки страницы устаревший участник неизвестен.
- CORS: запрос идёт на `sipServerUrl` и блокируется только у браузерного приложения, открытого с другого origin (на тестовом сервере `OPTIONS` этого маршрута отвечает `405` без CORS-заголовков, проверено с `http://127.0.0.1`). Тогда звонок после обрыва или отбоя отклоняется сетевой ошибкой, а попытка перезвона считается неуспешной. Приложение с того же origin, что и сервер, и Electron-приложение со страницей из `file://` (`webSecurity` включён) не затронуты: на тестовом сервере запрос из собранного desktop-клиента проходит. Шаг выполняется у всех потребителей SDK, включая гостевые звонки.
