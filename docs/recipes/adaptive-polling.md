# Адаптивное опрашивание видеопотоков

## Принцип работы

Пока балансировка активна, `VideoSendingBalancer` периодически сверяет то, по чему он в последний
раз выставил параметры отправителя, с текущим состоянием: тот же ли видео-отправитель, тот же ли на
нём трек и прежний ли у трека размер. Опрос адаптивный: чем дольше ничего не меняется, тем реже он
выполняется.

Сверка работает внутри SDK и отдельно не настраивается: класс опроса из пакета не экспортируется.

## Что делает опрос

| Ситуация                                    | Действие                                            |
| ------------------------------------------- | --------------------------------------------------- |
| Отправитель, трек и размер трека прежние    | Ничего: ни запроса статистики, ни чтения параметров |
| Изменился размер трека                      | Балансировка по новому размеру                      |
| Трек заменён мимо балансировщика            | Балансировка по новому треку                        |
| Сменился видео-отправитель                  | Балансировка нового отправителя                     |
| Предыдущая балансировка завершилась ошибкой | Повтор балансировки                                 |
| Предыдущая балансировка прошла без кодека   | Повтор балансировки, пока кодек не станет известен  |
| При замене трека не встали параметры        | Повтор балансировки                                 |

Параметры, которые отправителю выставил другой модуль, опрос не перезаписывает, пока не изменились
отправитель, трек или его размер.

## Алгоритм адаптации

| Ситуация                                               | Действие                        | Результат                    |
| ------------------------------------------------------ | ------------------------------- | ---------------------------- |
| **Балансировка изменила параметры**                    | Сброс интервала до минимального | Быстрая реакция на изменения |
| **Завершилась замена трека**                           | Сброс интервала до минимального | Новый трек проверяется сразу |
| **При замене трека не встали параметры**               | Сброс интервала до минимального | Повтор на ближайшем опросе   |
| **В соединении нет видео-отправителя с треком**        | Интервал не растёт              | Новый отправитель — сразу    |
| **Изменений нет или балансировка завершилась ошибкой** | Удвоение интервала              | Снижение нагрузки на CPU     |
| **Достижение максимума**                               | Ограничение интервала           | Предотвращение "заморозки"   |

Начальный интервал — 1 секунда, максимальный — 16 секунд. Следующий опрос планируется после
завершения балансировки предыдущего, поэтому при зависшем запросе статистики опросы не копятся.

## Когда опрос не идёт

- до запуска балансировки, в том числе пока запуск только запланирован;
- после `stopBalancing()` и событий, которые останавливают балансировку (`ended`, `failed`,
  `recv-session-started`, `recv-quality-changed`).
