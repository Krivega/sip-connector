# Причина отключения от сервера

Если входящий SIP BYE/CANCEL завершает сессию и содержит заголовок
`X-VINTEO-DISCONNECT-CAUSE`, коннектор добавляет `disconnectCause` в данные события:

- `call:ended`, `call:failed`, `call:ended:fromserver` — основной звонок;
- `incoming-call:failedIncomingCall` — входящий вызов до ответа.

Заголовок читается без учёта регистра через JsSIP. SIP-ответы, другие методы и локальное
завершение не интерпретируются как серверная причина. Коннектор не завершает вызов по
одному наличию заголовка: он обрабатывает события завершения, которые уже принял SIP-стек.

## Контракт

Из корня `sip-connector` экспортируются `EDisconnectCause`, `TDisconnectCause` и
`TCallEndEvent`:

```typescript
type TDisconnectCause = {
  raw: string;
  code?: number;
  key?: EDisconnectCause;
};

type TCallEndEvent = EndEvent & {
  disconnectCause?: TDisconnectCause;
};
```

`raw` — значение, возвращённое `getHeader` JsSIP, до числового преобразования коннектором.
Для разбора убираются окружающие пробелы. Принимается десятичная запись целого с
необязательным знаком; результат должен удовлетворять `Number.isSafeInteger`.

| Ситуация | Результат |
| --- | --- |
| Заголовка нет | `disconnectCause` равен `undefined`, прежние данные события сохраняются |
| Код известен | Заполнены `raw`, `code`, `key` |
| Целое число неизвестно | Заполнены `raw`, `code`, а `key` равен `undefined` |
| Значение некорректно | Сохраняется `raw`, `code` и `key` отсутствуют |

Пустая строка, `1003abc`, `1003.0`, `1e3`, `0x3eb` и небезопасное целое не становятся
известными кодами. Неизвестные и некорректные значения не вызывают исключение.

| Код | `EDisconnectCause` |
| --- | --- |
| 1000 | `INSUFFICIENT_LICENSES` |
| 1001 | `P2P_NO_ANSWER` |
| 1002 | `ROOM_CONNECTION_LIMIT` |
| 1003 | `DISCONNECTED_BY_MODERATOR` |
| 1004 | `CONFERENCE_FINISHED` |
| 1006 | `P2P_REMOTE_UNAVAILABLE` |
| 1007 | `MODERATOR_LEFT` |
| 1008 | `ANONYMOUS_CONNECTION_FORBIDDEN` |
| 1009 | `MODERATOR_REQUIRED` |

Коды 1005, 1010 и 1011 не входят в справочник и обрабатываются как неизвестные.

## Жизненный цикл

Стандартные `cause`, `originator` и исходный `message` JsSIP сохраняются. Исходный объект
события не мутируется. Политика повторного дозвона продолжает использовать стандартный
`cause`, а не `disconnectCause.key`.

Если вызов заканчивается во время установления, расширенное событие также передаётся
в отклонение Promise ожидания. `TCustomError` допускает необязательное `disconnectCause`.
После успешного установления причина приходит через событие завершения.

Для ожидающего входящего вызова сохраняются существующие данные звонящего. CANCEL с
причиной и BYE с причиной публикуются через `incoming-call:failedIncomingCall`. BYE без
заголовка не добавляет новое событие по сравнению с прежним поведением. После передачи
сессии на ответ входящий менеджер снимает добавленную подписку `ended`, и BYE обрабатывает
основной звонок. Существующая подписка `failed` сохраняется: её обработчик очищает
сохранённую входящую сессию и публикует событие, теперь с `disconnectCause` при наличии
заголовка. Фильтрация устаревших `failed` и изменение жизненного цикла этой подписки
не входят в доработку. Приложению следует учитывать `rtcSession` события, чтобы не
показывать причину старого вызова как причину завершения текущего.

## Использование в приложении

```typescript
import type { TCallEndEvent } from 'sip-connector';

const handleCallEnd = ({ disconnectCause }: TCallEndEvent) => {
  if (disconnectCause === undefined) {
    // Прежняя обработка соответствующего события.
    return;
  }

  // key известен: выбрать перевод; key отсутствует: показать нейтральную причину.
  // Текст и способ показа принадлежат приложению.
};

sipConnector.on('call:ended', handleCallEnd);
sipConnector.on('call:failed', handleCallEnd);
```

Не следует одновременно показывать причину из `call:ended:fromserver` и из
`call:ended`/`call:failed`: первое событие уже является производным от двух последних.
Также нужно согласовать обработку события с `.catch` операции установления, чтобы
не показывать вместе с конкретной причиной ещё и общую ошибку.

Коннектор не содержит локализованные сообщения и не определяет серверную бизнес-причину.

## Диагностика

В namespace `sip-connector:DisconnectCause` записываются `raw`, `code`, `key`, SIP-метод,
`Call-ID` и `CSeq`, доступные в сообщении. Для неизвестных данных значения полей могут
быть `undefined`. Целый SIP-пакет не записывается.

Это штатный debug коннектора: запись видна при включённом namespace. Постоянное
логирование в Web/Desktop, дополнительные идентификаторы приложения и локализация
реализуются на стороне приложения.
